# Patrones de resolucion de problemas

## Objetivo de este modulo

Aprender patrones mentales clasicos para resolver ejercicios DSA y problemas reales antes de memorizar algoritmos.

## Explicacion simple

Los problem solving patterns son formas repetibles de pensar. No son codigo para copiar: son herramientas para reconocer la forma del problema y elegir una estrategia.

## Por que importan

Antes de aprender arboles, grafos o algoritmos avanzados, conviene dominar patrones simples. Te ayudan en entrevistas, debugging, automatizaciones, dashboards y logica de negocio.

## Analogia cotidiana

Un patron es como una herramienta de cocina: no usas un cuchillo para revolver sopa ni una cuchara para cortar carne. En programacion, cada problema suele tener una herramienta mental adecuada.

## Metodologia

```txt
1. Entender el problema.
2. Escribir ejemplos simples.
3. Identificar patron probable.
4. Resolver manualmente.
5. Escribir pseudocodigo.
6. Programar en TypeScript.
7. Probar casos normales.
8. Probar casos borde.
9. Analizar complejidad basica.
```

## Como elegir un patron

| Senal del problema | Patron probable |
| --- | --- |
| Contar, comparar duplicados o frecuencias | Frequency Counter |
| Array ordenado y pares | Multiple Pointers |
| Subarray consecutivo, rachas o ventanas de tiempo | Sliding Window |
| Datos ordenados y busqueda eficiente | Divide and Conquer |

## Como Codex puede ayudarte sin darte todo

Pedile pistas graduadas, casos de prueba y revision de tu solucion. Evita pedir la respuesta final demasiado pronto.

```txt
Dame solo una pista sobre el patron probable. No me des codigo todavia. Luego revisa mi pseudocodigo y marcame errores.
```

## Mini ejercicio

Elegir patron para: contar pedidos por estado, encontrar dos precios que suman un presupuesto, mejor racha de ventas de 3 dias y buscar un ID en lista ordenada.

## Checklist de comprension

- Entiendo input, output y restricciones.
- Se pensar casos borde.
- Puedo elegir un patron probable.
